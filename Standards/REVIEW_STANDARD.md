## Стандарт завершения задачи

Действует для всех текущих и будущих проектов AI POS без исключений.

Задача не считается завершённой только на основании изменения кода, сохранения файла, прохождения линтера или статической проверки.

Обязательный этап завершения — предъявление пользователю фактического результата.

### Правила

1. Если результат можно открыть автоматически, Cursor обязан открыть его самостоятельно. Пользователь не должен искать папку, файл, адрес или приложение.
2. Для веб-проектов необходимо запустить приложение и открыть изменённый экран.
3. Для презентаций, Word, Excel, PDF и изображений необходимо открыть итоговый файл и показать изменённое место.
4. Для проектов без UI необходимо выполнить программу, тест или обработку и показать фактический вывод.
5. Если результат не удалось открыть, нельзя использовать статус «Готово». В этом случае используется формулировка «Изменения выполнены, но предъявление результата не завершено» с указанием конкретной причины и недостающего звена.
6. Запрещено без предварительной попытки автоматического открытия перекладывать запуск на пользователя.

### Визуальное подтверждение результата

Письменный отчёт не заменяет визуальную проверку.

Если задание изменяет интерфейс или поведение приложения, результат предъявляется на реальном работающем приложении. Снимок результата сохраняется вместе с завершённым заданием и остаётся доступным при возвращении к проекту.

Такое задание не считается предъявленным, пока визуальный результат не показан и не сохранён.

Если визуальный результат не требуется, причина указывается явно и сохраняется вместе с заданием.

### Жизненный цикл задачи

Получить задачу → Выполнить → Проверить → Предъявить результат → Подтверждение пользователя → Следующая задача.
