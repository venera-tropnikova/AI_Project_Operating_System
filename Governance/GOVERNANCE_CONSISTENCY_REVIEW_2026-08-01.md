# Governance Consistency Review — 2026-08-01

**Дата:** 2026-08-01
**Тип:** Consistency Review (точечная проверка состояния канона, не нормативный документ)
**Статус:** завершена; решений не принимает
**Ограничение:** новые сущности и новые правила этим документом не вводятся; только диагностика существующего состояния.

Этот документ — снимок состояния на конкретную дату, не вечный канон.
При следующей проверке ожидается отдельный файл: `GOVERNANCE_CONSISTENCY_REVIEW_<дата>.md`.

---

## 1. Область проверки

Проверяются только **нормативные документы Governance** — то есть документы, которые сами что-то предписывают или фиксируют статус принятия.

Из области проверки исключены:

- журналы (`DECISION_LOG.md`, `ARCHITECTURAL_OBSERVATIONS.md`) — они не обязаны ссылаться сами на себя;
- документы в статусе Draft, ещё не прошедшие Action Gate (`ETHICS.md`);
- рабочие материалы отдельных решений (Health Workshop / Review / Decision Package) — у них уже свой, отдельный и внутренне согласованный формат заголовка.

## 2. Уже канонические поля заголовка (найдено, не изобретено)

В проверяемых нормативных Governance-документах устойчиво используется один и тот же паттерн:

```
Статус: <значение>
Версия контура: Architecture Freeze v1.0
Связь: <связанные документы>
```

Отдельно, в point-in-time документах Health, используется другой, тоже согласованный паттерн:

```
Тип:
Статус:
```

## 4. Найденные несоответствия

1. **Отсутствие обратной ссылки.** CONSTITUTION.md и PIPELINE.md упоминают DECISION_LOG только в общей, процедурной форме («решения фиксируются там»), не как конкретную ссылку на запись, которой были приняты сами. ORCHESTRATOR.md не ссылается на DECISION_LOG вообще, хотя принимавшая его запись (D-2026-07-26-02) существует.

2. **Статус Accepted без подтверждающего решения.** CHANGE_PROTOCOL.md заявляет «Статус: Accepted», но ни одна запись DECISION_LOG.md не фиксирует его принятие — единственные упоминания файла случайны, внутри чужой записи (D-2026-07-27-01, про удаление `Procedures/`). Это не вопрос отсутствующей ссылки, а вопрос непроверяемости самого статуса.

3. **Разные имена одной сущности.** «Связь:» (связанные документы вообще) и «Решение:» (конкретная принимающая запись, уже используется в HEALTH.md) — два разных понятия, которые в ходе обсуждения чуть не были случайно объединены под третьим новым именем («Принято решением:»). Прецедент уже есть в каноне под именем «Решение:».

## 7. Рекомендуемые действия

Отдельно от фактов, как предложения к дальнейшему Governance-решению:

- привести ORCHESTRATOR.md к существующему паттерну — добавить `Решение: D-2026-07-26-02`;
- привести CONSTITUTION.md и PIPELINE.md к тому же паттерну, указав конкретную принимающую запись вместо общей ссылки на DECISION_LOG;
- принять отдельное решение Governance по CHANGE_PROTOCOL.md: либо понизить статус до Draft, либо провести через Action Gate сейчас, с записью в DECISION_LOG. Запись задним числом не создаётся;
- вопрос о Governance Document Standard отложить: расширять формат заголовка нет оснований, пока не исчерпана попытка привести документы к уже найденному паттерну.
